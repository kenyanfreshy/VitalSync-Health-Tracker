## 6. iOS Deployment Notes

### Foundation Models (iOS 26+)
Foundation Models Framework is gated behind `@available(iOS 26.0, *)` in Swift and `parseInt(Platform.Version) >= 26` in TypeScript. On iOS 15.1–25.x, the app automatically falls back to Gemini. No user-facing change occurs — the provider attribution string in the AI card footer updates to reflect which provider is active.

### App Intents (iOS 16+)
App Intents are registered via the native `AppIntentsModule.swift`. Deep-link routing is handled by `use-app-intents.ts` which listens for `Linking` events with the `vshtapp://` scheme. The intent registry is the single source of truth for all 8 intents.

### EAS Build
To trigger the iOS production build after pushing:
```bash
eas build --platform ios --profile production
```
The commit `fb4df22` is ready to build. Push is pending a valid GitHub PAT with `repo` write scope for `kenyanfreshy/VitalSync-Health-Tracker`.

## 7. Known Limitations

The following items are intentionally deferred to a future release:

- **Foundation Models on-device inference** requires a physical iOS 26 device or simulator. The Swift module is implemented and wired, but cannot be validated in the current sandbox environment. Validation should occur during TestFlight testing on an iOS 26 device.
- **App Intents Siri registration** requires a native build (EAS) to register intents with the iOS system. The intent registry and deep-link handler are complete; Siri phrase recognition will activate after the first TestFlight install.
- **RTM item: EAS build trigger** — the GitHub push is blocked by an expired PAT. The commit is local and ready; a fresh PAT with `repo` scope will unblock the push and subsequent EAS build.
